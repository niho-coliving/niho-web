# 保存・作業復元・版履歴の契約

`PageEditor` の保存状態の表示、自動保存、端末内の緊急復元、409競合の比較、版履歴、公開前レビューの契約です。既存の `EditorAdapter` だけを実装したホストでは、従来の手動保存と公開確認がそのまま動きます。保存状態の表示、409 の比較、「保存して移動」、「再試行」は元のメソッドだけで動くため、どのホストでも使えます。自動保存、端末内の復元、版履歴は、ホストが props と任意メソッドで明示的に有効にした場合だけ表示します。

文書の差分、履歴項目の検証、復元ストアは React 不要の `@niho/web/history` から使えます。ホストの `prepareRelease` で公開差分を作るときも同じ `diffDocuments` を使えます。

## 保存状態

ツールバーは常に次のいずれかを表示します。

| 表示 | 状態 |
| --- | --- |
| 保存済み（時刻） | 作業コピーが保存済みの基準と一致 |
| 未保存の変更あり | 手動保存で、保存していない変更がある |
| 自動保存を待っています | 自動保存が有効で、待機時間内 |
| 保存中… | 下書き保存の通信中 |
| 保存できませんでした | 通信失敗等。「再試行」で同じ内容を保存 |
| 競合しています | 409。「比較する」で最新の保存内容と見比べる |
| 部品が競合しています | 共通部品の保存が 409。「部品を読み直す」で最新の部品を読み直す |
| オフラインです | `navigator.onLine` が false。編集は画面内（と、有効なら端末内）に保持 |
| ログインを確認してください | 401 / 403。再認証後に「再試行」 |

「競合しています」「部品が競合しています」「ログインを確認してください」は解決するまで表示します。「保存できませんでした」「オフラインです」は未保存の変更がある間だけ表示します。処理中の表示は「保存中…」のように末尾に「…」を付けます。

保存・競合・失敗のどの場合も、作業コピー、undo/redo、入力途中の値、元の `expectedVersion` を保持します。自動で上書き・merge・再読込をしません。

## 自動保存

```tsx
<PageEditor adapter={adapter} autosave={{ delayMs: 2000 }} />
```

- `autosave` を省略すると手動保存だけです。`true` は待機 2,000ms、`{ delayMs }` は 100〜60,000ms を指定できます。有効な場合、スタッフはツールバーの「自動保存」をこの画面の間だけ切り替えられます。
- 編集が確定してから待機時間だけ変更が無ければ、`saveDraft` を呼びます。入力途中・無効な値が残る間、公開確認・移動確認・履歴表示中、オフライン、未解決の競合やログイン切れの間は保存しません。
- 同時に送る保存は1件だけです。保存中の変更は、完了後に改めて待機して保存します。
- 失敗・競合・ログイン切れでは自動保存を止め、状態と操作を表示します。オフラインで失敗した後、接続が戻ったときは1回だけ再試行します。手動保存だけのホストでは、接続が戻ると「保存できませんでした」と「再試行」を表示します。
- 応答は、送信時のサイト・ページ・locale と version が現在の作業コピーと一致する場合だけ採用します。保存中にページやサイトを切り替えることはできず、移動確認では「保存して移動」を選べます。遅れて届いた応答で別のページを上書きしません。

自動保存はホスト側の下書きを更新します。自動保存の `saveDraft` の要求には `trigger: 'autosave'` が付きます（手動保存では付きません）。ホストは手動保存と同じ認可・楽観ロック・revision 採番を行い、必要なら履歴上で `autosave` として区別してください。自動保存が公開を行うことはありません。

## 端末内の緊急復元

ブラウザや端末を閉じた後、保存失敗の後に作業を戻すため、ホストは復元ストアを渡せます。

```tsx
import { createBrowserRecoveryStore } from '@niho/web/history';

const recovery = createBrowserRecoveryStore({ scope: opaqueStaffKey }); // メール等をそのまま使わない
<PageEditor adapter={adapter} recovery={recovery} />
```

- 省略時は端末へ何も保存しません。未公開原稿を端末に置くため、ホストは利用する端末・アカウントの方針に合わせて有効にしてください。
- 保存する内容は、対象（サイト・ページ・locale）、編集開始時の version と revision、作業コピーの文書、更新時刻だけです。入力途中の値、token、認証情報、ロック理由は保存しません。
- `scope` はログイン中のスタッフごとに異なる opaque な値にします。同じ端末の別スタッフの退避内容は読みません。
- 削除条件: 保存成功、変更の破棄（移動・再読込・最新内容の読込）、復元内容の破棄、期限切れ（既定72時間）、`clear()`。ホストはログアウト時に `clear()` を呼んでください。1件の上限は既定2MBで、超える場合は退避せず画面に知らせます。
- 既定の保存先は `localStorage` です。独自の `EditorRecoveryStore`（`read` / `write` / `remove`）を渡せば、ホストのサーバーや IndexedDB にも置けます。

文書を開いたとき、読込んだ内容と異なる退避内容があれば「保存されていない変更があります」と日時を表示し、比較・復元・破棄を選べます。退避後に別の保存があった場合、復元の前に最新の保存内容との差分を表示し、確認した場合だけ作業コピーへ適用します。

復元を選ぶまでの間、退避内容は上書きも削除もしません（移動して戻っても残ります）。待機中の退避はページを閉じるとき（`pagehide`）にも書き込みます。退避に失敗した場合は、文書を開くごとに1回まで知らせます。

### 共通部品の退避

共通部品（[共通部品契約](component-contract.md)）の変更はページの文書に含まれないため、サイト単位で別に退避します。adapter に `components` があり、復元ストアが任意の `readLibrary` / `writeLibrary` / `removeLibrary` を3つとも実装している場合だけ動きます。`createBrowserRecoveryStore` は3つを実装しており、ページと同じ `scope`・期限・1件の上限を使います（鍵はサイトごとに1件）。`components` の無いホストと、ページ用の3メソッドだけのストアでは従来どおり、部品の変更を端末へ置きません。

```ts
// 独自の EditorRecoveryStore で部品も退避する場合
readLibrary(siteId: string): StoredLibraryRecoveryEntry | null | Promise<StoredLibraryRecoveryEntry | null>;
writeLibrary(entry: EditorLibraryRecoveryEntry): void | Promise<void>;
removeLibrary(siteId: string): void | Promise<void>;
```

- 保存する内容は、サイト ID、読み込んだときのライブラリの version（`baseVersion`）、手元で変えた部品 ID ごとの変更前の version（`changed`。手元で追加した部品は `null`）、作業コピーのライブラリ、更新時刻だけです。入力途中の値、token、認証情報、使用状況は保存しません。
- 部品の変更が確定してから 800ms 後と、ページを閉じるとき（`pagehide`）に書き込みます。
- 削除条件: 保存成功（部品の保存が成功し、未保存の部品の変更が無くなったとき）、破棄（「部品を読み直す」で変更を破棄したとき・サイトの移動で「変更を破棄して移動」を選んだとき・復元の提案で「破棄」を選んだとき）、期限切れ（既定72時間）、`clear()`。公開前の確認は部品の変更を保存した後にしか始められないため、公開した時点で未保存の部品の退避内容は残っていません。復元の提案を表示している間だけは、保存・公開でも消さず、「復元する」か「破棄」を選ぶまで残します（期限切れでは消えます）。
- 別サイトへは復元しません。読み出した退避内容は、内容の `siteId` とライブラリの `siteId` が開いているサイトと一致し、部品の規則で検証できた場合だけ使います。一致しない内容は使わずに消します。
- サイトを開いたとき（部品ライブラリを読み込んだとき）に退避内容を確認し、保存先でその後に変わっていない部品だけを最新のライブラリに重ねて「保存されていない部品の変更があります」と提案します。保存先の変更は部品の version で判定します（部品の内容を変えると version が上がる契約）。退避した後にほかの保存で変わった部品と、手元で追加した ID が最新では別の部品になっている場合は、最新の内容を残し「ほかの保存で変更されたため復元しない部品」として名前を表示します。重ねた結果が部品の規則に合わない場合は「最新の共通部品と合わないため、復元できません。」と表示し、「破棄」だけを選べます。
- 「復元する」は部品の作業コピーへの通常の変更で、保存するまでほかの文書には反映されません。編集中のページが重ねた部品で展開できない場合は復元しません。

## 409競合の比較

競合したとき、「比較する」で最新の保存内容を `readDocument` で取得し、あなたの編集との差分を表示します。

- 「最新の内容を読み込む」: あなたの編集を破棄して最新の内容に切り替えます。
- 「あなたの編集で上書き保存」: 差分を確認したチェックの後だけ、最新の version と revision を基準に保存します。最新の内容と同じ場合は保存しません。
- 「閉じて編集を続ける」: 何も変えません。

2人が同時に編集した場合も、両者の内容を見比べてから、どちらを残すかを明示的に選びます。

共通部品の保存の競合は「部品が競合しています」と表示し、「部品を読み直す」で最新の部品を `readLibrary` から読み直します。未保存の部品の変更を破棄する前に画面内で確認し、ページの変更は残します（[エディター契約の共通部品](editor-contract.md#共通部品)）。

## 差分の表し方

`diffDocuments(before, after)` は、ページタイトル、公開メタ情報、トークン、文字スタイル、要素・業務ブロック・部品のインスタンス（id ごと）の順に、人が読める箇所名と変更前後の値を返します。画像の素材参照、業務ブロックの表示領域の見た目、文字スタイルの割り当ても対象です。追加・削除された要素の子孫は、いちばん外側の要素の1行にまとめます。「位置」は同じ親に残った兄弟の中での順序が変わった場合だけ出し、前後の追加・削除だけでは出しません。値は最大200文字で、空文字は「（空）」、値が無い場合は「（なし）」と表示します。

## 版履歴

ホストが任意メソッドを実装すると、ツールバーの「履歴」から STUDIO の「バージョン管理」に近いパネルを開けます。開いている間、右レールは要素・ページ・サイトのタブの代わりに版の一覧を表示します。

```ts
type EditorRevisionEntry = {
  id: string;                 // opaque
  revision: number;
  kind: 'draft' | 'autosave' | 'snapshot' | 'publish' | 'rollback';
  createdAt: string;          // ISO 8601
  actor?: string;             // 表示名だけ。メール・ユーザーIDは返さない
  label?: string;
};

listRevisions({ target, cursor? }, signal): Promise<{ entries: EditorRevisionEntry[]; next?: string }>;
readRevision({ target, id }, signal): Promise<{ document: unknown }>;
createSnapshot({ target, expectedVersion, label }, signal): Promise<{ status: 'saved'; entry: EditorRevisionEntry } | { status: 'conflict' }>;
```

- 一覧は新しい順で、日時・実行者・種類・名前を表示します。「さらに表示」で `next` を使って続きを取得します。
- 一覧の先頭は「現在の編集内容」です。版を選ぶと履歴モードになり、キャンバスにその版を読み取り専用で表示し、上部に日時・種類と操作を出します。編集・保存・公開・プレビューの切替は履歴モードを閉じるまで止まります。「差分を見る」で現在の作業コピーとの差分を表示し、「この版を復元」でその版の内容（タイトル・公開メタ情報・トークン・文字スタイル・本文）を作業コピーへの通常の編集として適用します。復元は元に戻す／やり直すの対象で、保存するとサーバーが新しい revision を採番します。古い revision を再利用しません。
- 公開版のうち `releases` に含まれる版は、公開確認つきの rollback も選べます。
- スナップショットは保存済みの状態にだけ名前を付けて記録します。ホストは `expectedVersion` を検証し、新しい履歴項目として返してください。
- ホストは保存・自動保存・スナップショット・公開・rollback の実行者と日時を監査記録として保持し、パッケージやブラウザには表示名だけを返します。

コメントや共同編集の表示は履歴パネルに混ぜません。今後は別の adapter として追加します。

## 公開前レビュー

`prepareRelease` の plan に、任意で次の項目を返せます。

```ts
url?: string;          // このページの公開URL。domain から始まる完全な URL
affected?: { kind: 'shared' | 'page' | 'site'; name: string; detail?: string }[];
```

確認画面は、反映先ドメイン、公開URL、ページ、影響する共通部品・ページ・サイト設定、検索結果に出る情報、差分を表示し、明示チェック後だけ公開できます。`url` が `domain` で始まらない plan は受け付けません。

ホストは `confirmationToken` を対象文書・version・ドメイン・action・rollback revision・差分に結び付け、短い有効期限と一回限りの利用を実装し、`release` で認可と version を原子的に再検証してください。

## 漏えいを防ぐ前提

- パッケージはログ・URL・query に文書や token を出しません。版の識別子は opaque な値として扱い、URL に載せません。
- 履歴とプレビューは認証済みの画面の中だけで表示します。公開プレビューを作る場合は [ページ管理の契約](page-contract.md) の `PREVIEW_RESPONSE_HEADERS` と `preview: true` を使います。
- 個人情報・秘密を文書、履歴の名前、スナップショット名に入れないよう、ホストの保存APIでも検査してください。
