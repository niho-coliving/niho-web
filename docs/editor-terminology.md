# 編集画面の用語と構造

Studioの公開仕様を基準に、利用者が編集対象と変更の影響を理解できる名称を使う。独自の「共通枠」「共通ページ」「正本」は画面へ出さない。

| 用語 | 対象 | 例 |
| --- | --- | --- |
| ページ | URLを持つ画面。動的ページのテンプレートもこの一覧に置く | ホーム、法人プラン、記事詳細テンプレート |
| セクション | ページ内の大きなまとまり | メインビジュアル、料金、よくある質問 |
| コンポーネント | 再利用するデザイン要素 | ヘッダー、ナビゲーション、フッター、カード |
| スタイル | 再利用する文字と色の設定 | テキストスタイル、カラー |
| アセット | 画像やファイル | 写真、ロゴ、背景画像 |

## 編集入口

- ページパネルは通常ページとテンプレートを表示する。サイト共用のヘッダーなどはページの検索・フォルダ・件数へ混ぜない。
- コンポーネントパネルは、サイト共用パーツと再利用ライブラリを同じ入口に集める。両方を持つサイトでは「サイト全体」と「再利用」で整理する。
- サイト共用パーツは「コンポーネントを編集」から開く。編集中の名前と使用先への公開影響を示し、「ページに戻る」で元のページへ復帰する。通常のページ切替と同じ未保存確認、入力中の保護、読取専用、翻訳の制約を通す。
- 再利用コンポーネントは「コンポーネント本体」と「配置したコンポーネント」を区別する。公開された変更項目を配置先で変えても、ほかの配置先は変わらない。
- 予約・価格・送信などを持つ業務ブロックは用途を分けて表示し、登録済みの配置・編集制約を保つ。

## 保存・公開の互換性

`EditorPage.kind: "shared"` は、既存ホストがサイト共用パーツの保存・公開を担うための互換契約として維持する。UIではコンポーネントとして扱うが、ライブラリへ複製したり、配置・削除・切り離しなど未対応の操作を作らない。通常ページのJSONにヘッダー／フッターを複製しない。

ホストのカタログは、検証済みの `kind`・`path`・`visibility`・`published` をエディターへ引き継ぐ。ページIDの名前やサイト名から共通エディターが種類を推測しない。

サイト共用パーツは、下書き保存で公開サイトを変更せず、その文書を公開した時点で使用先へ反映する。再利用ライブラリは各使用先文書の公開時に展開されるため、保存後も各ページの公開が必要。使用件数が文書数しか分からない場合に、到達する公開ページ数として表示しない。

この整理は編集の情報構造を統一するもので、任意のページへの共用ヘッダーの割当・非表示など、新しい保存スキーマやホスト機能は追加しない。将来それらを追加する際も、同じコンポーネントの概念と配置設定を使う。
