# 共通エディターの利用契約

`@niho/web/editor` は認証済みスタッフ向けの React client component です。左の追加・ページ・レイヤー等のパネル、中央のライブキャンバス、右の要素・ページ・サイト設定を提供します。既存サイトの認証や API をパッケージから直接呼びません。

編集画面は左のツール列とページパネル、中央のキャンバス、右のインスペクタを共通workspaceに置きます。キャンバス下部のツールバーで表示幅、右パネル上段で倍率を変更します。左パネルを閉じてもツール列を残し、ツール選択で再度開けます。接続されていない素材機能等の入口は表示しません。workspaceは100dvhで高さを確定し、stageとパネル内だけをスクロールします。狭い画面ではパネルをキャンバス上のoverlayとして開閉して編集操作を維持します。

ホスト固有の戻る操作や識別表示は `toolbarStart` に渡します。サイト名による表示分岐は契約に含めず、すべてのホストが同じworkspaceを使います。旧 `toolbarLayout` propは削除しています。

## ホストへの接続

```tsx
'use client';
import { PageEditor, type EditorAdapter, type EditorBlockRegistry } from '@niho/web/editor';

// ここではホストが所有する認証済みクライアントを渡す。
export function StaffPageEditor({ adapter, blocks }: {
  adapter: EditorAdapter;
  blocks: EditorBlockRegistry;
}) {
  return <PageEditor adapter={adapter} blocks={blocks} />;
}
```

React 18.3 または 19 と、同じ版の React DOM を利用側で用意してください。`adapter` と `blocks` は module scope / `useMemo` 等で参照を安定させます。ホストの通常の再描画で作り直すと一覧・文書の再読込が起こるため、同じ編集セッション内では差し替えません。Next.js では adapter や registry の関数を Server Component から props で serialize せず、ホストの Client Component 内で組み立てます。

| adapter メソッド | 役割 |
| --- | --- |
| `listSites(signal)` | 編集権限のあるサイトと、許可済みの HTTPS 公開 origin 一覧 |
| `listPages(siteId, signal)` | 指定サイトで編集権限のあるページ・locale の一覧 |
| `readDocument(target, signal)` | 文書、opaque な `version`、データ連動値のロック、戻せる公開版 |
| `saveDraft({ target, document, expectedVersion }, signal)` | 楽観ロック付き下書き保存。成功時は新しい version とサーバー採番の revision、競合時は `status: 'conflict'` |
| `prepareRelease(request, signal)` | 公開 / rollback の正確な対象ドメイン、公開内容との差分、確認 token を発行 |
| `release(plan, signal)` | 確認済みの内容を公開 / rollback。成功時は最新 snapshot、競合時は `status: 'conflict'` |
| `preparePageChange` / `applyPageChange`（任意） | ページの作成・複製・名前とURLの変更・公開切替。影響の確認と一回限りの確認 token。[ページ管理の契約](page-contract.md) |
| `readSiteSettings` / `saveSiteSettings`（任意） | サイト共通の公開情報。楽観ロック付き |
| `listRevisions` / `readRevision` / `createSnapshot`（任意） | 版履歴の一覧・読み取り専用の表示・名前付きスナップショット。[保存・履歴の契約](save-history-contract.md) |

`listPages` の各ページに任意で `path`・`kind`（page / template / shared）・`visibility`・`published` を返すと、左のページパネルにフォルダ・種別・公開状態を表示します。任意メソッドを実装しないホストでは、ページ操作とサイト設定の保存を表示しません。

target は `siteId/pageId/locale` の組です。文書の組と一致しない読込結果は受け入れません。ホストは各呼出しで現在のセッションの認証・サイト/ページ権限を確認し、文書を `@niho/web/core` で検証してください。UI の選択値やロック表示をサーバーの認可の代わりにしません。

## 読み取り専用の原文

既存の業務原稿を仮想ページとして確認する場合、`readDocument`の現在snapshotに`readOnly`を返せます。省略した既存hostは従来どおり編集可能です。

```ts
{
  document,
  version,
  readOnly: {
    reason: "この公開テキストは業務編集画面が正本です。",
    editUrl: "/staff/business/public-text/experience",
    editLabel: "業務原稿を編集"
  }
}
```

`reason`は必須の1〜500文字、`editLabel`は任意の1〜80文字です。`editUrl`はホストが決めた1〜2,048文字のNIHO-app内root-relative routeまたは資格情報を含まないHTTPS URLだけを許可し、`http:`、`javascript:`、`data:`、protocol-relative、fragment-only、制御文字を拒否します。URLを表示文言から組み立てません。外部HTTPSの場合は新しいtabを`noopener noreferrer`で開きます。

エディターは理由と正本へのリンクを明示し、該当documentのtitle / meta / text / image / style / structure、追加・複製・削除、undo/redo、下書き保存、公開・rollback、履歴復元、snapshot作成、端末recovery、page操作を入口で止めます。プレビュー、要素選択、サイト・ページ・locale移動、履歴の閲覧は可能です。ポリシーは現在snapshotからsessionへだけ保持し、履歴文書や端末recoveryから復元しません。遅れて届いた別targetのsnapshotを採用しません。

これはdocument-levelの表示ポリシーで、認可機構ではありません。ホストは`saveDraft`、公開、page操作等の各書込APIで現在の正本ポリシーを再読込し、read-only targetへの直接要求も403等で拒否してください。原文snapshotのポリシーを派生言語へコピーせず、その派生snapshotに`readOnly`が無ければ編集できます。別の共通部品master編集、site設定、素材libraryの権限もこの値から推測しません。

`AbortSignal` は読込の切替と unmount 時に abort します。公開処理は signal が abort されてもサーバーで成立する可能性があるため、ホスト側で結果の照会と重複実行の防止を実装します。例外の生メッセージ・token・秘密を UI に表示しません。

## 楽観ロックと編集の保持

`version` は HTTP ETag や DB の更新番号を文字列にしたもの等、ホストが管理する opaque な値です。文書内の `revision` と別に扱います。下書き保存時は `expectedVersion` と保存先の現行版を原子的に比較し、サーバーが現行 revision より大きい safe integer を採番して文書に設定し、必ず新しい version とともに返します。同じ site/page/locale/revision に異なる内容を保存しません。

成功応答は `{ status: 'saved', version: 'new-version', revision: 2 }` の形式です。送信文書の revision は編集開始時点の基準であり、採番をクライアントへ任せません。ホストは revision 以外の送信内容を変形せず保存してください。応答の revision が送信時以下・非整数・safe integer 外の場合、エディターは応答を採用せず、手元の編集と元の version を保持します。

HTTP 409 は adapter で `{ status: 'conflict' }` へ変換します。`status: 409` を持つ例外も競合として表示します。他の例外は一般的な保存失敗として扱います。どちらの場合も文書・undo/redo・元の expectedVersion を保持します。競合の自動上書きや自動 merge はしません。再読込で手元の変更を破棄する場合は、明示確認が必要です。

保存中も編集を続けられます。成功時は現行の作業コピー・undo/redo履歴・保存開始時の文書から作る保存済み基準を、返された revision に揃えます。内容と履歴の順序を保つため、保存中の追加編集は未保存のまま残り、undo/redoで保存時点に戻すと正しく保存済みになります。次の保存では新しい version と revision を送信し、サーバーがさらに新しい revision を採番します。保存処理中のページ切替や公開操作はできません。

作業コピーと履歴の revision は最新の保存先を表す基準です。編集中の内容をその revision の公開済み文書として扱わず、永続化・公開する際は保存で採番した不変の文書を使います。rollback で過去の内容を復元するときも、異なる内容へ古い revision を再利用せず、新しい revision の文書を返してください。

編集履歴はメモリ内で最大50操作です。undo/redo・保存済み表示は文書内容と保存済みの基準を比較します。サイト/ページ移動・再読込は未保存の文書と入力途中の値を破棄する前に確認します。タブを閉じる際もブラウザへ離脱確認を要求します。自動保存、ブラウザや端末を閉じた後の復元、版履歴は、ホストが明示的に有効にした場合だけ動作します。[保存・作業復元・版履歴の契約](save-history-contract.md) を参照してください。

## 安全な入力と編集範囲

テキスト、リンク、画像（素材ライブラリまたはURL）/alt、背景画像、文字色・背景色・フォント・サイズ・余白・Flex/Grid・位置・幅の段ごとの指定、共通カラー・テキストスタイル等の共通の値を編集できます。要素や登録ブロックの追加、複製、親/兄弟間の移動、削除、undo/redo に対応します。複製時はノードIDとHTML IDを作り直し、複製内のアンカーとARIA ID参照を付け替えます。

追加パレットのセクション・ボックス・テキスト・見出し・リッチテキスト・画像はクリックで選択した親の末尾へ追加するか、キャンバス／レイヤーへドラッグして挿入位置を指定します。既存要素も選択後にキャンバスまたはレイヤーから移動でき、選択枠の右下をドラッグすると現在選んだ編集幅の幅・高さを一操作として変更します。キーボード向けには追加先の選択と上／下／末尾への移動、右インスペクタのサイズ欄を残します。不正な入れ子、循環、ロックされた変更はモデルの検証で拒否します。

### 挿入カタログの拡張

`PageEditor` の任意prop `builder` で、信頼済みホストが通常の `PageNode` 部分木を追加パレットへ登録できます。公開型と標準定義は `@niho/web/builder` から読み込みます。標準カタログは従来のセクション（`section`）、ボックス（`div`）、テキスト（`p`）、見出し、リッチテキスト、リンク、画像、カルーセル、トグルを維持し、リスト、横並び、グリッドも一般的な組み立て部品として提供します。追加パレットは従来の簡潔な項目を表示し、リスト、横並び、グリッドや独自構造はhostが `builder.insertions` へ明示した場合だけ表示します。同じ定義IDを指定すると標準項目を置換し、新しいIDは標準項目の後へ追加します。

```tsx
import type { BuilderDefinition } from '@niho/web/builder';

const builder = {
  insertions: [{
    id: 'feature-card',
    label: '特徴カード',
    group: 'サイト部品',
    glyph: '◇',
    create: ({ id, target }) => ({
      type: 'element', id: id(), tag: 'article', attrs: { lang: target.locale }, children: [
        { type: 'element', id: id(), tag: 'h2', children: [{ type: 'text', text: '特徴' }] },
        { type: 'element', id: id(), tag: 'p', children: [{ type: 'text', text: '説明' }] },
      ],
    }),
  }],
} satisfies BuilderDefinition;

<PageEditor adapter={adapter} blocks={blocks} builder={builder} />
```

`create` は実行時だけ存在するtrusted host codeで、返す全element / component / instance IDを必ず `id()` で採番します。返した部分木は現在文書へ仮に加え、既存の `parsePageDocument` で深さとノード数、ID重複、HTML入れ子、属性、style、登録block、共通部品を全体検証してから検証済みのコピーを走査し、通常の `add` 操作へ渡します。配置先での入れ子も `add` 時に再検証します。`insertableBlocks` は部分木に直接ある業務ブロックだけでなく、配置する共通部品が内包する業務ブロックにも適用します。共通部品masterの循環・配置制約、snapshot locks、read-only、訳文側の構造編集禁止も標準項目と同じ経路で適用します。定義からscript、style element、イベント属性、任意CSSを文書へ保存することはできません。

本文・見出しはキャンバスでダブルクリックして直接編集できます。リッチテキストは許可済みの段落・見出し・箇条書き・太字・斜体・リンクを文書ノードとして保存します。貼り付けはプレーンテキストに限定し、contenteditable の HTML は保存せず、許可済みノードへ変換して既存validatorを通します。Escapeで編集を取り消し、Cmd/Ctrl+Enterまたはフォーカス移動で確定します。保存対象はあくまで検証済みのPageDocumentです。

インスペクタは定義済みのプロパティだけを表示します。HTML、JS、任意CSS、未知propsを直接入力する欄はありません。値は core validator を通ってから文書へ適用し、無効値は入力欄に残して理由を表示します。入力途中または無効な値が残る間は保存・公開・構造操作を止め、「入力を取り消す」で適用済みの値へ戻せます。

サイズは数値＋単位の選択（px / % / rem / vw / vh と「自動」等のキーワード、共通の値）で入力します。数値だけの px は数値のまま保存します。直接 `1.5rem` や共通の値の `@space` も入力できます。対応値は[文書・描画契約](document-contract.md)に従います。値を空欄にするとその指定を削除します。選択肢の表示名は日本語で、内部のプロパティ名や CSS の識別子は表示しません。

## 見た目のインスペクタ

要素を選ぶと右パネルに要素名と条件スタイル、その下に対象に応じたタブを表示します。テキストは「テキスト / ボックス / 変形 / 設定」、画像は「画像 / ボックス / 変形 / 設定」、ボックスは「ボックス / 変形 / 設定」です。選択したタブの内容だけを表示し、画像タブでは素材・URL・レスポンシブURL・代替テキスト、ボックスタブではレイアウト・並び・外観・位置、変形タブでは状態・移動・回転・二軸の拡大縮小・傾き・原点・アニメーション・登場、設定タブでは要素の種類・リンク・ブロックprops・表示幅を編集します。ボックス内の位置と詳細は折りたたみで、初期状態は閉じています。段バーはスタイル欄の先頭に置き、各タブから利用できます。

余白は一括 1 欄と上下左右 4 欄、角丸は一括と四隅を切り替えられます。一括から個別へは shorthand を 4 方向へ展開し、個別から一括へは 4 方向が同じ値ならその値、異なれば上（左上）の値にします。切替は 1 回の操作なので 1 回の undo で戻ります。並ぶ向きと配置（`flexDirection` と `flexWrap`、`justifyContent` と `alignItems`）も 1 回の操作で同時に変更します。

## 幅の段と状態表示

`breakpoints` で段の名前と開始幅を渡せます（省略時は `[{ minWidth: 768, label: 'タブレット' }, { minWidth: 1280, label: 'PC' }]`）。minWidth は 320〜3840 の整数・昇順、label は 40 文字以内で、不正な値は既定値に戻します。文書（ノードと文字スタイル）で使われている他の幅も `1024px〜` のような段として追加します。

段バーの「編集する幅」は「基本」と各段を明示して選びます（初期値は「基本」）。文書は mobile first なので、「基本」の指定はすべての幅に効きます。「表示幅」（320 / 375 / 768 / 1280 / 1440px）を変えても編集する段は変わらず、要素の選択を変えても段と反映する範囲を保ちます。表示幅の段と編集する段が違うときは「表示中の幅（タブレット 768px〜）の段を編集」で合わせられます。キャンバス上部には「表示中: 1280px（PC の段）」を表示します。

最上段以外では「反映する範囲」を選べます。初期値は広い側（「すべての幅」／「768px 以上」）で、通常の cascade どおり上の段で上書きした項目以外に効きます。「〜767px だけ」／「768〜1279px だけ」を選ぶと、編集は次の段の開始幅より広い幅の見た目を変えません。この編集は 1 回の操作（1 回の undo）で、変更前に次の段の開始幅で効いていた値（ノードの下位の段 → テキストスタイルの順）を次の段へ写してから、選んだ段へ値を書きます。広い幅に値が無い場合、tag に依存しない初期値があるプロパティ（幅・高さ・位置・重ね順・並ぶ向き・要素間の余白・不透明度・角丸・背景色・枠線の種類・はみ出し・画像の収まり等）は初期値を写し、それ以外（配置方式・余白・文字・色・揃え等）は「先に「768px 以上」で値を入れてください。」と案内して拒否します。余白は shorthand と上下左右を組として扱います。段の色は基本が中立、2 段目が青系、3 段目が橙系、以降は交互です。表示幅が編集中の範囲の外（狭い側・広い側のどちらでも）にあるときは「表示中の 375px にはこの指定は反映されません」と、範囲内の幅で表示するボタンを出します。

各項目は、その段で指定した値を段の色で塗り、項目名の横の ↺ で「この幅の指定を解除」できます（「〜だけ」の範囲では広い幅の見た目を保ったまま解除します）。指定が無い項目は、効いている値を入力欄の placeholder に、出どころを 1 行の短いヒント（「継承: 基本」「継承: タブレット」「継承: 見出し」、選択肢では「継承: 見出し · 太い」）で表示し、詳しい文（「テキストスタイル『見出し』から継承」等）は title と aria-describedby で伝えます。上の段で同じ項目を上書きしている場合は「別の値: PC」と表示します。保存済みの文書と値が違う項目には中立色の小さな点（title「保存前の変更」）と読み上げ用の「保存前」を付けます。入力途中は破線の枠、無効値は理由を表示して入力を残し、適用済みの値は変えません。数値と単位、色見本と HEX と不透明度はそれぞれ 1 つの枠にまとめ、フォントは「指定なし・ゴシック体・明朝体・等幅・共通のフォント・その他…」の 1 つの選択で指定します。

## スタイルパネルと共通の値

左のツールレールの「スタイル」で開きます。スタイルパネルは「カラー」「テキスト」「その他」の小タブと、一覧の見出し行（右端の＋で追加）を持ちます。一覧は各行 1 行目に名前、2 行目に値（`#195640 / 50%` 形式やサイズ）と使用数を表示し、カラーは色見本、テキストは `Aa` の見本（そのスタイルの太さとフォント）を付けます。行を開くと同じパネル内で名前・値・段ごとの文字サイズの上書きを編集できます。値を変えると使用箇所すべてへ反映し、反映先の数と使用箇所（押すと要素を選択）を表示します。要素の選択中は文字色・背景色（インスペクタで選んでいる段と範囲へ）やテキストスタイルを適用できます。

削除は確認してから実行し、使用中の箇所は今の見た目のまま個別の指定に変えます（カラー等の参照は現在の値へ、テキストスタイルは宣言を各要素へコピー）。インスペクタのテキストスタイルの「切り離す」も同じです。どの操作も通常の編集と同じ undo/redo・保存・競合の扱いです。`StyleLibrary` は props（文書・選択・apply・select・disabled 等）だけで動く部品です。

## ライブプレビュー

インスペクタとスタイルパネルの入力中（キー入力・色の選択のドラッグ・スライダー）は、文書のルールに合う値だけをキャンバスへ仮に反映し、履歴には積みません。確定・取り消し・選択の変更・undo/redo・保存・ページ移動で仮の反映をやめます。

### サイト全体の共通表示を差し込む

`PageEditor` の任意prop `previewComponent` は `EditorCanvasPreviewProps` を受けるReactコンポーネントです。展開済みの現在の文書（編集中の訳と未保存の変更を含む）、幅、breakpoint、`mode`（edit / preview / history）、`readOnly`、編集の基準版 `baseVersion`、履歴の選択版 `historyRevision`、従来の描画結果 `children` を、既存Canvasと同じiframe・error boundary内で受け取ります。共有部品の編集中は合成文書と部品ライブラリの版を渡し、それ以外はページ下書きの版を渡します。コンポーネントの参照は安定させて渡してください。React contextも引き継ぎ、iframeの言語は表示中の文書のlocaleへ合わせます。

コード管理ページではホスト所有の版固定表示部品を返し、通常の編集文書は `children` をそのまま返せます。未指定なら既存描画を維持します。渡された文書を直接変更せず、保存・翻訳・公開・予約などの副作用を起こさないでください。プレビューと履歴の読み取り専用状態、フォーム送信・リンク移動の抑制は従来のCanvasが扱います。

ホスト画面のglobal CSSはiframeへ自動で入りません。表示部品に対応する信頼済みCSS・font・画像を同じ版で供給し、iframeのsandboxを緩めないでください。データ取得・権限確認・版の選択はホストの責任で、共有editorは任意のHTMLや実行文字列を受け取りません。

## 変形とアニメーション

インスペクタの「変形」タブで、状態・変形・アニメーション・登場を編集します。状態・移動・回転などはタブを開くとすぐ表示し、幅ごとの非表示は「設定」タブに置きます。

- **状態**: 「通常 / ホバー / フォーカス / 押下中」を選ぶと、状態に使える見た目（文字色・背景色・枠線の色・不透明度・下線・移動・回転・拡大）だけを表示し、キャンバスでは選択中の要素にその状態を擬似クラスなしで強制表示します。ホバーを初めて作るときは「キーボードのフォーカス時も同じ見た目にする」（初期オン）で、フォーカスにも同じ値を 1 回の操作で書きます。状態の見た目はすべての幅に適用します。
- **変形**: Studio の順に移動（X・Y）、回転（°）、拡大・縮小（X・Y を % で表示し数で保存）、傾き（X・Y の °）、原点を表示します。段（幅）と反映する範囲の扱いは他の見た目と同じです。
- **アニメーション**: Studio の順にイージング、時間・遅延（秒）を表示します。状態の見た目が無い要素では使えず、理由を表示します。
- **登場**: 効果（なし・ふわっと表示・下から・上から・左から・右から・拡大）、きっかけ（ページを開いたとき・画面に入ったとき）、時間・遅れ・動き方。画面に入ったときはスクロール量に合わせて動き、時間と遅れは使いません。「動きを減らす設定の利用者には動きなしで表示します」を常に表示します。
- **表示する幅**: 段ごとのチェックで非表示を切り替え、隣り合う段は 1 つの範囲にまとめて保存します。すべての幅で非表示にはできません。レイヤー一覧では、表示中の幅で非表示の要素を薄くして「この幅で非表示」と表示します。

`builder.motions` には再利用する `MotionPreset` を登録できます。保存形式は新しいwire fieldではなく、既存の `NodeStyle.base`（変形・transitionだけ）、`states`（hover / focus / active）、`appear`（enter）です。適用時は定義が宣言したpathだけを既存styleへ重ね、切替・解除時は直前の定義が所有するpathのうち現在値が一致するものだけを外します。手動で設定した状態色や回転、`responsive`、`hidden`、`textStyle`、背景や余白等の通常styleを保持し、適用・切替・解除はいずれも1操作としてundoできます。

```ts
const builder = {
  motions: [{
    id: 'quiet-lift',
    label: '静かに浮かす',
    description: 'ポインターとキーボード操作で少し上へ動かします。',
    style: {
      base: { transitionDuration: 220, transitionTimingFunction: 'ease-out' },
      states: { hover: { translate: '0 -4px' }, focus: { translate: '0 -4px' } },
    },
  }],
} satisfies BuilderDefinition;
```

標準定義には hover / focus / enter の例がありますが、標準 `PageEditor` は説明的なプリセット選択を自動表示しません。利用者は Studio に合わせた「通常 / ホバー / フォーカス / 押下中」、変形、イージング、時間、遅延、登場の各欄で直接設定します。hostが独自UIやcommandから定義を適用する場合も、`styleProperties`、locks、read-only、訳文制約を通り、サイト共通tokenを含む実効styleで既存validatorを適用時と所有権復元後の2回通します。runtimeでも `base` の非モーションproperty、未知のstate / field、任意のkeyframes、selector、CSS、JavaScriptを拒否します。公開CSSと `prefers-reduced-motion` の扱いは手入力した演出と同じです。

キャンバス上部の「動きを再生」（aria-pressed、初期は停止）で動きを切り替えます。停止中は iframe 内の animation と transition を止め、編集中に選択枠がずれないようにします。再生にすると描画を作り直して登場をもう一度見せます。ツールバーの「プレビュー」中は常に動きを再生し、状態の強制表示はしません。

追加パレットの「インタラクション」から、JS を使わない「カルーセル」（横スクロールとスナップ。容器は `tabIndex: 0` と名前を持ちキーボードで届く）と「トグル（開閉）」（`details` / `summary`）を配置できます。キャンバスのクリックでは開閉しません。

## 業務ブロックの見た目

registry の各ブロックに `styleProperties` を指定すると、そのブロックで変えられる見た目を限定できます。インスペクタは指定外の項目を表示せず（「このブロックで変更できる見た目だけを表示しています。」）、モデルも指定外のプロパティの変更を「このブロックでは変更できない見た目です。」で拒否します。テキストスタイルの適用は `'textStyle'`、状態は `'states'`、登場は `'appear'`、幅別の非表示は `'hidden'` を含めたときだけ許可します。省略時はすべての見た目を変更できます。スタイル操作から props は変わりません。

```tsx
const blocks = {
  PublicNotice: {
    props: { heading: { type: 'string', required: true } },
    styleProperties: ['marginTop', 'marginBottom', 'backgroundColor', 'textStyle'],
    component: ({ heading }) => <aside>{heading}</aside>,
  },
} satisfies EditorBlockRegistry;
```

### 表示領域（slots）

registry の `slots` で表示領域を宣言したブロックは、内側の見た目を領域ごとに整えられます。宣言・文書・CSS の契約は[業務ブロックの表示領域契約](block-slot-contract.md)を正とします。

- **選び方**: キャンバスでブロックの中の `data-nw-slot` の要素を押すと、そのブロックと領域を選びます。同じ領域の要素（繰り返すカードなど）すべてを破線で示します。右パネルの「表示領域」の一覧からも選べます。一覧には、領域ごとに「見た目を変更できます」/「見た目は変更できません」と、値がホストのデータのときは「値は〇〇が正本です」を表示します。ページのインスタンスの中では、従来どおりインスタンス全体を選びます。部品の編集中は、部品の中のブロックの領域を選べます。
- **領域の右パネル**: 「ブロック名 · 領域名」と「ブロック全体に戻る」を表示します。`data` があれば理由と正本を注記として表示し、入力欄は出しません。`text` があれば「〇〇の文字」でその string prop だけを編集できます（文字数の上限と残りを表示）。見た目は通常のインスペクタと同じ欄で、その領域で許可されたプロパティだけを表示します。状態・登場・幅別の非表示・テキストスタイル・背景画像は領域では使えないため表示しません。幅と高さの両方が許可された領域だけ、キャンバスのサイズ変更の枠を出します。
- **反映**: 領域の操作は `slotStyle` として1回の履歴にまとめ、モデルでも許可外のプロパティを拒否します。値（料金・在庫・予約先など）を入力する欄はありません。
- **プレビュー用の描画**: registry の各ブロックに `preview` を渡すと、キャンバスと共通部品の縮小表示ではそれで描画します。副作用（予約・決済・データ更新）を起こさず、実データに近い見本を複数件表示してください。公開用の `PageRenderer` は引き続き `component` を使います。

## キャンバス

「表示幅」は iframe の実 viewport を変更するため、media query と固定位置のレイアウトを確認できます。編集中のキャンバス内のリンクやブロック操作は選択に使い、プレビュー中もリンク遷移とフォーム送信を止めます。サーバー描画用と同じ `PageRenderer` と host registry を使います。

iframe は scripts を許可しない sandbox として表示し、公開ページのCSS・fixed要素が編集UIへ重ならないようにします。registry は依然として信頼できるホストコードです。React の effect や親 window からの処理までは隔離できないため、プレビュー用ブロックで課金・予約・データ更新などの副作用を起こさないでください。

`insertableBlocks` を空配列にすると、登録済み業務ブロックの新規追加を隠し、既存ブロックの表示 props 編集だけを残せます。省略時はすべての登録ブロックを追加できます。サイト固有の配置条件は保存 API でも検証してください。

## 素材ライブラリ

`PageEditor` に `assets`（`AssetLibraryAdapter`）を渡すと素材ライブラリを使えます。`listProviders` を実装するホストでは、左レールに「アップロード」「ストック」「接続」を出し、それぞれサイトへのアップロード素材・ストック素材・接続済みCMS素材だけを表示します。「接続」はCMS素材を参照する入口で、外部サービスの接続設定はホスト側の設定画面が担当します。インスペクタの画像選択では、配置を許可された出所をまとめて選べます。`listProviders` のない既存ホストは単一の「素材」パネルを維持します。`assets` を渡さない場合は、画像を追加して「画像 URL」で指定する案内を表示します。adapter・素材の形・ホストの責務は[素材ライブラリ契約](asset-contract.md)を正とします。

- 「アップロード」では検索、種類（画像・動画・PDF）、フォルダで絞り込み、アップロード、名前・代替テキストの初期値・フォルダの更新、使用状況の確認、未使用素材の削除ができます。容量と1ファイルの上限、受け付ける形式は adapter の応答に従い、送信前にも確認します。「ストック」はライセンスと利用条件の確認後に取り込み、「接続」はCMSで公開を許可された素材の参照・配置を行います。権限や素材が未接続の場合は理由を表示し、一覧を要求しません。
- 素材の詳細から「選択中の画像を置き換え」「選択中の要素の背景にする」「ページに追加」を選べます。インスペクタの「画像を選ぶ」「背景画像を選ぶ」は、同じパネルを選択モードで開き、画像を1回選ぶと適用して閉じます。選択モードでアップロードした1枚もそのまま適用します。
- 置き換えたときは素材の代替テキストを要素の alt の初期値にします。配置後の alt は要素ごとに編集します。
- 配置できるのは確認済みの JPEG・PNG・WebP・AVIF・GIF 画像だけです。動画・PDF 等は一覧と詳細に表示しますが、配置操作を出しません。
- 入力途中の値がある間、保存・公開処理中、確認ダイアログの表示中は配置できません。配置・置き換えは通常の編集と同じく validator、ロック、undo/redo を通ります。ロックされた画像（`asset` / `attrs.src`）や背景（`style`）は変更できません。
- このページで使っている素材は削除できません。「このページの使用箇所を置き換え」で別の画像へまとめて置き換えられます。他ページの下書き・公開版で使われている素材も、ホストが返す使用先を表示して削除を止めます。
- 選択モードは、どのパネルを開いていても「素材」パネルに切り替えて表示し、閉じると元のパネルへ戻ります。パネルを切り替えても、キャンバスの選択と入力途中の値は保持します。

画像の選択パネルには「すべて」と各出所（サイト・CMS 画像・ストック等）の切替と「最近使った」が表示されます。出所の権限に応じて、アップロード・編集・削除の操作を出し分けます。ストック等の配置前には `acquireAsset` でライセンスを記録します。

プレビューは `adapter.resolveAssets` で取得した URL で描画し、解決できない画像は破線の枠で表示します。「最新の文書を再読込」と公開の後は、解決と素材一覧を取り直し、非公開化・削除された素材をプレビューから外します。保存する文書には素材参照だけを入れ、URL を入れません。

## データ連動値のロック

ブロックに共通のデータ連動値は registry に明示します。

```tsx
const blocks = {
  PublicNotice: {
    props: {
      heading: { type: 'string', required: true },
      count: { type: 'number', required: true },
    },
    defaultProps: { heading: 'お知らせ', count: 3 },
    lockedProps: { count: '公開データから取得する件数です。ホスト側で管理します。' },
    component: ({ heading, count }) => <aside>{heading}: {count}</aside>,
  },
} satisfies EditorBlockRegistry;
```

ページ固有のロックは snapshot の `locks` に `{ nodeId, fields, reason }` として返します。fields は `props.count`、`attrs.href`、`style.base.color`、`style`、`children`、`*` 等の文書フィールドです。text node 自体はIDを持たないため、その親の `children` をロックしてください。

画像の `asset`、`attrs.src`、`attrs.srcSet` は1つの画像ソースとして扱います。いずれかをロックすると、残りの指定による差し替えも入力・履歴・復元の検証で拒否します。altは別フィールドです。素材IDを使う画像には独立した `src` / `srcSet` を保存できません。

ロックされた欄は理由付きで無効化し、モデル側でも編集・削除・undo/redoによる変更を拒否します。データ連動値を含む要素やその祖先の複製・削除も拒否し、移動は値を変えない場合に許可します。ロックは編集補助なので、同じ制約を保存・公開APIでも適用してください。価格・在庫・予約の取得や計算をパッケージへ持ち込みません。

## 公開 / rollback の二段階確認

公開操作は保存済みの文書だけに許可します。ホストは初回など保存済み下書きがない snapshot に `hasSavedDraft: false` を返すと、公開前確認を無効化して下書き保存を案内できます。省略した既存ホストの挙動は変わりません。保存成功後はエディターがこの状態を true に進め、再読込時はホストの現在値を使います。ホストは公開 API 側でも保存済み下書きを再確認してください。prepareRelease は現在の公開内容と保存済み下書きの差分をホスト側で計算し、人が理解できる `path/before/after` の文字列配列として返してください。rollback の場合は指定した公開版を反映した結果との差分にします。UI は plan をコピーして保持します。

plan の target、expectedVersion、action、rollback revision が要求と一致し、domain が listSites の許可済み HTTPS origin に含まれることを確認してからダイアログを開きます。origin は `https://example.com` の形式で、パス・資格情報・末尾 `/` を含めません。対象ドメインと差分を表示し、明示チェック後だけ実行ボタンを有効にします。確認中は背後の編集を無効化します。

ホストは confirmationToken を対象文書・version・ドメイン・action・rollback revision・正確な差分に結び付け、短い有効期限と一回限りの利用を実装してください。release 時も認可と version を原子的に再検証し、UI から渡された domain や changes を権限の根拠にしません。token をログや永続文書に保存しません。

公開409は現在の編集内容を保持して確認を閉じます。通信失敗は「成立したか不明」として扱い、ホスト側で公開状態を確認するよう表示します。成功時はホストが返す最新 snapshot を検証して読込むため、文書と version を必ず最新状態で返してください。

## 共通部品

adapter に `components`（`EditorComponentAdapter`）があると、左のツールレールの「部品」パネルに共通部品が表示されます。ない場合は業務ブロックの一覧だけで、表示も通信も従来どおりです。モデル・展開・ホストの責務は[共通部品契約](component-contract.md)を正とします。

- **読込**: サイトを選ぶと、ページより先に部品ライブラリを読みます。読めない場合は消えない通知「共通部品を読み込めませんでした。部品を含むページは表示できません。」を出し、部品を含まないページの編集は続けられます。使用状況は後から取得し、取得中は「使用状況を確認中」、失敗時は「使用状況を取得できません」と表示します。編集中のページは、未保存の内容で数え直します。
- **部品パネル**: 名前で検索でき、種類（ヘッダー・ナビゲーション・セクション・パーツ・フッター）順に並びます。各カードは、見えている文字・画像に合わせて拡大した縮小表示、名前、種類と使用数を持ちます。縮小表示も部品の編集と同じく、サイト共通に同名の定義がある値はサイトの定義で描きます（ページに置いたときと同じ見た目。[サイトとページのスタイル所有権](#サイトとページのスタイル所有権)）。サイト設定を読むホストでは、読み込むまで縮小表示の枠だけを出します。「配置」（キャンバスへのドラッグも可）、「編集」、「その他」（名前を変更・複製・削除）を選べます。追加が許可されていない業務ブロックを含む部品の配置と、使用中・使用状況が分からない部品の削除は、理由を表示して止めます。
- **部品にする**: 要素を選んだ右パネルの「部品にする」から、名前と種類を指定して登録します。選んだ要素は同じ ID のインスタンスに置き換わります。祖先の要素、選んだ要素またはその子孫にページ固有のロックがある場合は押せません。サイト共通スタイルを使うページでも登録でき、保存するページにはページ所有の定義だけを残します。
- **インスタンス**: キャンバスでは部品の中のどこを押してもインスタンス全体を選び、紫の破線で囲みます。中の文字は直接編集できず、インスタンスを中に含む文字要素も直接編集できません。右パネルでは「ページごとの値」を変えられ（部品の値と同じにすると上書きを外します）、「部品の値に戻す」「整理する」（使われなくなった値）と「部品を解除」（確認あり）を選べます。外枠の見た目はこのページだけに適用されます。
- **部品の編集**: パネルの「編集」、右パネルの「部品を編集」、またはインスタンスのダブルクリックで開きます。キャンバス・レイヤー・右パネルは部品の外枠だけを持つ文書を扱い、上部の帯に「保存すると使用中の n 文書に反映されます」と表示します。部品の中で追加したノードの ID は `n1`, `n2`… です。外枠の外（ページ直下）には置けず、外枠の外へのドロップは外枠の末尾へ置きます。右パネルでは名前・種類・使用中の文書と、要素ごとの「ページごとに変えられるようにする」を設定できます。テキストスタイルの作成・適用、ページのタイトル・公開情報の変更、版の履歴と作業の復元は、理由を表示して止めます。キャンバス・インスペクタ・スタイルパネルは、ページに置いたときと同じく、サイト共通に同名の定義がある値をサイトの定義で表示・検証します（所有は[サイトとページのスタイル所有権](#サイトとページのスタイル所有権)）。
- **履歴**: 元に戻す・やり直すは、部品の編集中は部品の履歴に、それ以外はページの履歴に効きます。部品とページの内容が合わなくなる移動（ページが使う部品を、部品の履歴で消す等）は「共通部品とページの内容が合わなくなるため、この操作はできません。」で止めます。編集中のページを展開できなくなる部品の変更も受け付けません。
- **保存**: 「下書き保存」と自動保存は、部品 → ページの順に保存します（自動保存の `saveLibrary` には `trigger: "autosave"` を付けます）。部品の保存が競合（409）・失敗した場合はページを保存せず、両方の変更を保持します。競合では保存状態を「部品が競合しています」にして自動保存を止め、「部品を読み直す」を出します（同じ version のまま送り直しても競合するため「再試行」は出しません）。そのほかの失敗では「再試行」を出します。部品の保存中は部品の編集だけを止め、ページの編集は続けられます。
- **部品を読み直す**: 保存状態の「部品を読み直す」で `readLibrary` から最新の部品を読み、作業コピーを変える前に影響を確かめます。読み込めなければ何も変えずに知らせます。サイトスタイルの編集中は、ページの編集と同じく押せません。ページの部品の解除は「部品を解除」と同じ編集で、ページのロックとサイト共通スタイルも同じく扱います。
  - 未保存の部品の変更があれば、画面内の確認「共通部品を読み直す」に破棄される部品（追加・変更・削除）を並べ、「最新の部品を読み込む（部品の変更を破棄）」を押した場合だけ読み直します。「閉じて編集を続ける」では何も変えません。未保存の部品の変更が無く、ページにも影響が無ければ、確認せずに読み直します。
  - ページの変更（未保存のものを含む）は残します。編集中のページが最新の部品で展開できない場合は、確認の画面に次の扱いを表示します。
    1. 最新に無い部品と、手元で追加した部品と同じ ID で別の内容の部品が最新にある場合は、そのインスタンスを手元の定義で「部品を解除」と同じく通常の要素にします。文字と見た目は残り、ほかの人の部品が黙って置き換わって表示されることはありません。
    2. それでも展開できなければ、手元で変更した部品のうち最新と内容が違うもののインスタンスも同じく解除します。
    3. それでも展開できない場合（ほかの保存で部品の外枠が変わり、ページの置き場所に合わない等）は読み直さず、「最新の共通部品では、編集中のページを表示できないため読み直せません。」と対象の部品名を表示します。ページでその部品を「部品を解除」するか削除してから、もう一度読み直せます。読み取り専用のページでは解除できないため、別のページを開いてから読み直します。
  - 読み直した後は部品の元に戻す・やり直すを最新の内容から始め、選択を外します。編集中の部品が最新に無ければページに戻ります。「部品が競合しています」は消え、使用状況を取り直します。破棄した部品の変更は端末の退避内容からも消します。ページの元に戻す・やり直すは残しますが、最新に無い部品と、手元で追加した ID が最新では別の部品になっている部品を使っていた版へは移れません（移るとほかの人の部品が表示されるため、その版より遠い履歴も消します）。
- **作業の復元**: ページの退避内容は、開いた時点の部品の内容で検証します。部品の内容と合わず展開できない退避内容は、削除せずに残し、「端末に残っていた変更がありますが、共通部品の現在の内容と合わないため復元できません。」と表示します。版の表示・409 の比較・版の復元も、部品の内容で検証してから行います。部品の変更は、ホストが渡した復元ストアが部品用のメソッド（`readLibrary` / `writeLibrary` / `removeLibrary`）を持つ場合だけ、サイトごとに端末へ退避します（`createBrowserRecoveryStore` は持っています）。サイトを開いたときに退避内容があれば、キャンバスの上に「保存されていない部品の変更があります」と復元する部品を表示し、「復元する」「破棄」を選べます。部品の編集中は復元できません。内容と削除条件は[保存・作業復元・版履歴の契約](save-history-contract.md#共通部品の退避)を正とします。
- **公開**: 部品に未保存の変更がある間と部品の編集中は「公開前の確認」を押せず、理由を画面に表示します。公開確認の要求には、表示中のライブラリの `componentsVersion` を入れます。公開前レビューの「影響する共通部品」には、ホストが返した項目に加え、このページで使っている部品を「このページで n か所に配置」として表示します。
- **移動**: ページの切替・再読込では部品の編集を終えますが、部品の未保存の変更は残します。サイトを切り替えるときは、部品の未保存の変更も確認の対象です。「変更を破棄して移動」を選ぶと、部品の退避内容も消します。

```sh
npm ci
npm test
npm run typecheck
npm run demo
```

`http://127.0.0.1:4173` の動作例は公開可能なインメモリ adapter を使います（別のポートで開く場合は `PORT=4180 npm run demo`）。ホームと「私たちについて」には共通部品のサイトヘッダーとセクション見出しを置いており、部品の編集・ページごとの値・展開済みの差分での公開を試せます。変更と「公開」はメモリ内だけに反映され、プロセス終了で失われます。素材ライブラリには生成した見本画像・PDF・動画のメタデータが入っており、アップロードしたファイルもデモサーバーのメモリにだけ保存します。外部API・認証・実サイトへ接続しません。サムネイルや配信 URL を別ドメインから読む場合は、CSP の `img-src` にそのドメインを追加してください。

テストは core 連動編集、構造操作、ロック、履歴、素材のアップロード・置き換え・保存・再読込と削除防止、実DOMでの入力・保存・409/通信失敗時の保持・保存中編集、公開ドメイン/差分確認、未保存移動、共通カラーの作成・適用・反映、段ごとの上書きと解除・表示幅で段が変わらないこと・「〜だけ」の編集と公開用 CSS との一致、無効値の拒否、余白の一括⇔個別の undo、業務ブロックの見た目の限定、テキストスタイルの適用と切り離し、ホバー・フォーカスの作成と公開用 CSS での再現、幅別の非表示、登場の設定、動きの停止・再生、キャンバスで開閉しないこと、キーボードでの状態の切替を確認します。利用先への導入では認証・同時編集・本番公開処理・CSP・アクセシビリティとサイト固有ブロックの表示を確認してください。インラインCSSと `srcdoc` iframe を許可する CSP が必要です。

## サイトとページのスタイル所有権

スタイルパネルはサイト設定の読書きがあるホストで「このページ」「サイト共通」を表示し、各行にも所有者を示します。ページの override を優先した同じ実効値を、フィールド・CSS・キャンバスへ使います。共有定義をページ側で編集するとページの override を作ります。

部品の編集中は「このページ」「サイト共通」を切り替えません。部品が参照する値の所有者は部品ライブラリで、ページに置いたインスタンスはページ > サイト共通 > ライブラリの順に重ねて描画します（[共通部品契約](component-contract.md#展開の規則)の規則 4）。部品の編集はページを持たないため、ライブラリの値にサイト共通の同名の定義だけを重ねた実効値を、フィールド・CSS・キャンバス・検証へ使います。サイト設定を読むホストでは、各行の所有者を「共通部品」「サイト共通」と示します。

- **共通部品**（ライブラリにだけある値）: 部品の編集で作成・変更・削除でき、部品ライブラリへ保存します。新しい値の名前はサイト共通の名前と重ねません（重ねるとサイトの定義で表示されるため）。
- **サイト共通**（ライブラリの写しと同名の定義がサイトにある値）: 写しを変えても見た目が変わらないため、部品の編集では名前・値の変更と削除を止め、「サイト共通の値のため、部品の編集では変更できません。」と、サイト設定を保存できるホストでは「ページに戻り、スタイルの「サイト共通」で変更してください。」を表示します。部品の中の要素への適用はできます。
- サイト共通にしかない値は部品の編集では一覧に出さず、選べません。ライブラリへ保存する tokens には、サイトの定義を書き込みません（写しは部品にした時点の値のまま残り、ライブラリ単体の検証に使います）。

サイトスタイルの編集中はページの編集・下書き保存・ページ移動・公開を止め、設定を先に保存します。保存失敗・409では入力を保持します。影響ページ数は各ページの検証済み参照と override から求め、検証できない場合は共通スタイル保存を許可しません。パネルでは保存済み設定との差分を表示し、公開前ダイアログではホストの公開版との差分・全影響ページを表示します。

部品のインスタンスを置いたページは、公開時と同じく部品を展開して影響を求めます（tokens はページ > サイト共通 > ライブラリの順。[共通部品契約](component-contract.md#展開の規則)の規則 4）。部品の中だけで使う値も、サイト共通の追加・変更・削除（削除した値はライブラリの写しで描きます）で描画に使う値が変われば影響ページに数え、ページの同名の定義が優先されて見た目が変わらない場合は数えません。部品ライブラリを読めない場合は展開できないため、検証できない場合として共通スタイルの保存を許可しません。

ページの未保存の変更や、ページの欄に入力途中の値が残るあいだは「サイト共通」を編集できず、その理由を表示します。「サイト共通」の欄自身の入力途中はこれに数えず、そのまま確定できます（入力途中として保存・公開・構造操作を止める扱いは、ほかの欄と同じです）。

「サイト共通へ移す」はページ定義と、文字スタイルが参照するページ token を移行候補として作り、同名衝突の旧値と新値を明示して確認します。確認直後もページ定義を保持します。サイトの保存が成功した時点でページ側の定義削除を編集履歴へ反映し、その後にページ下書きを保存します。サイト保存の失敗・取消でページを参照切れにしません。途中で閉じても、先に保存した共通定義と元のページ override は両立します。

共有定義の削除は `siteStyleCapabilities.atomicReferenceDetachment` が宣言されたホストだけで許可します。全ページの原子的な切り離し、公開 snapshot、権限・競合・キャッシュの責務は [サイト設定の契約](page-contract.md) に従います。エディターだけで複数ページへ順次書込みを行いません。
